# Frontend rules

- **Reuse before writing.** Search `src/components/ui`, nearby screens, and `src/hooks` for existing controls and behavior. Extend a shared component when the change belongs in every caller. Keep feature-specific code next to the feature. Use the existing Button, Select, Dialog, and `FormField` where they fit, and use semantic Tailwind tokens from `src/app/globals.css`.
- **Own controls in City.** Keep Base UI primitives behind City’s shadcn/ui components in `src/components/ui`. Use the local `Select` for standalone choices and `SelectField` for React Hook Form choices. Add a missing control there so screens can share its markup, interaction, and styling.
- **Keep React state with its owner.** Store transient state in the component that owns it and lift it to the closest common parent when controls need to agree. Derive values during render, keep rendering pure, update state immutably, and use stable record IDs for list keys. Handle user actions in event handlers. Use effects to synchronize with external systems and clean up subscriptions and timers.
- **Use the App Router boundaries.** Use Server Components for pages by default. Scope `use client` to components that need interaction, hooks, or browser APIs. Keep the 3D map lazy-loaded and preserve the 2D fallback.
- **Keep workflow behavior consistent.** Use the existing workspace store and schemas across Runs, Releases, and the City map. Put shared rules and validation in `src/lib/workspace` and keep server-side validation authoritative. Use the current plan revision and approval state for execution controls.
- **Make controls accessible.** Use links for navigation and buttons for actions. Give controls accessible names, visible focus, and sufficient contrast. Keep dialogs usable by keyboard and restore focus on close. Pair status colors and icons with readable labels. Associate field errors with their inputs.
- **Handle the states people can reach.** Account for loading, empty, saving, success, error, and blocked states where they occur. Prevent duplicate submissions, keep input on recoverable errors, and show the next action.
