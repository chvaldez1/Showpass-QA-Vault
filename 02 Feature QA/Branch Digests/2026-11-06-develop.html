Keep in mind: Voucher restoration requires its rollout switch. Existing backend fee and return rules still apply.

Regression for the whole QA team

This is the shared QA regression selection: protect established journeys around the changed code. Owning teams remain responsible for the full acceptance matrix for Hive, developer keys, Bandsintown, shared-pool Inventory, the new guest-list form, pricing preview and other feature changes.

Before execution, use the release build, team-confirmed Venue flags/settings, prepared disposable records, approved sandbox payments and supported cleanup. Start with the First checks. Reuse existing saved cases/automation where their assertions prove the stated result; no Qase or automation coverage audit was performed.

Client scope: Public Web, existing Widgets and Web Box Office. The desktop app starts the same Box Office page, and mobile/POS reuses the shared basket service, so include staff-sale smoke on supported Electron and mobile/POS builds. Exercise physical terminals, printing and mobile scanning on the actual configured devices; browser results cannot replace device proof. Use only controls the client supports.

Buy an ordinary ticket on a clean successful path. Confirm one charge, one saved order, the exact issued tickets, correct fees/taxes and Showpass earnings, one Inventory reduction and usable receipt links.
