# Legacy Check In — Qase-ready coverage

**Target:** [Check In, suite 184](https://app.qase.io/project/SPT?suite=184), under Dashboard (78). Scope is the **legacy `/dashboard/events/check-in/` page and its backend behavior**. No Next.js pages or frontend repository were inspected for this request. Browser inspection is smoke evidence only; **web-app owns expected eligibility, validation, permissions and saved results**.

**Published:** [Check In suite 184](https://app.qase.io/project/SPT?suite=184) now contains **34 direct cases**. Created **SPT-5473–5501** (29 cases) and updated **SPT-1663/1664** after explicit approval. Full-field readback verified all **31 writes / 99 step rows**. Proposed revisions **SPT-1665/5151 remain held**; SPT-5123 and all five membership cases in suite 185 are unchanged. Publication is not execution.

**Important limits:** Product-only preset creation has a backend/legacy-UI mismatch; product-only typed barcode scanning has a second source integration risk. Existing duplicate/wrong-code assertions from SPT-1664 are preserved in the separately published SPT-5473/5474; these were created before SPT-1664 was narrowed. The date-range case is corrected from event start time to event end time. These drafts are not a production-readiness claim; scanning, saving presets and exports were not executed.

Use ordinary Dashboard navigation and select the correct organization before each run. **Scan** records admission or product pickup; **Return/Undo** reverses that record, not a payment refund. A **preset** is a named saved item selection. Keep physical devices and camera tests separate from a typed barcode in a browser. Platform/View tables are execution selections, not native parameters; no full Cartesian matrix is implied.

Follow the Check In link on an event’s Edit Event page and verify that its event selection is carried into legacy Check In. Run each EventKind separately without scanning or saving anything.

| EventKind | Prepare and open |
| --- | --- |
| Single | A single event with a redeemable ticket type and a controlled purchase |
| Recurring | A recurring event parent with at least two occurrences containing redeemable ticket types and controlled purchases |

| Platform | View |
| --- | --- |
| Dashboard | Desktop |
| Dashboard | Mobile |

**Preconditions:**

* Employee permissions: **Manage Events**, **Scan Tickets** and **Select Items to Scan**.
* Use the legacy Check In page: organization flag `enable_check_in_nextjs_embed` is off, with no Check-in preview opt-in for this employee and organization.
* Record the prepared event’s name, ticket types and, for Recurring, its occurrence names/dates. Have an unrelated event available as an excluded control.

**Tags:** dashboard, check-in, events

**Parameters:**

EventKind: Single, Recurring

**Steps:**

| Step Action | Data | Expected Result |
| --- | --- | --- |
| Open Dashboard → Events → Manage Events and select Edit for the prepared event. | Use the Description table. | Edit Event shows the intended event and a Check In link. |
| Select Check In. |  | Legacy Check In opens its filter dialog with the selected event, or the recurring parent’s occurrences and ticket types, already selected. |
| Inspect the selected events/types, then select Continue → Tickets. |  | The prepared event’s purchases are available; the unrelated event is excluded and no admission has been created. |

**Postconditions:**

* No event, purchased item or preset data is changed.
