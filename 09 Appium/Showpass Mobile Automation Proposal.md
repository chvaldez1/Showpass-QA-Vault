# Showpass Mobile Automation Proposal

## Goals

Choose the best framework for the Showpass mobile app on iOS and Android. Compare Appium + WebdriverIO, Detox, and Maestro in Showpass Beta.

1. Cover the full set of Showpass’s user-facing React Native screens and controls across the Buyer and Organizer builds. Include shared components such as filters, lists, forms, and sheets, plus the gestures and state changes they support.
2. Automate the WebViews inside the app, including guest checkout and signed-in pages such as **My orders**. Verify the handoff between native screens and embedded pages.
3. See how easy it is to add and fix tests and keep hundreds running reliably. Keep browser coverage in Playwright. [Playwright checkout tests](https://github.com/showpass/showpass-playwright/tree/2e5addb9be4881af4d951bca5323568cfdfee381/tests/core/checkout)
4. Run mobile tests in GitHub Actions on both platforms and save logs and screenshots on failure.
5. Explore camera, payment, and printer automation on real devices as a possible extension.

## Recommendation

**Choose Appium + WebdriverIO.** It’s the best documented fit for Showpass. It documents the WebView and frame switching needed to start on the native **Explore** screen and reach Stripe’s separate card fields on both platforms. Appium also documents the pinch gesture used by the iPad seat map. Detox’s secured-field tools are iOS-only, and Maestro’s pinch request is still open. Stripe card entry on the installed Showpass Beta builds still needs verification. [Showpass card fields](https://github.com/showpass/showpass-frontend/blob/f1ca342cd7d5b109446631515c2248c17251dcc6/packages/core/src/shared/modules/payments/stripe/StripeElement/StripeElement.web.tsx#L228-L258) · [Seat-map gestures](https://github.com/showpass/showpass-frontend/blob/f1ca342cd7d5b109446631515c2248c17251dcc6/packages/mobile/src/components/Seating/SeatingMap/SeatingMapContext.tsx#L1134-L1182)

**Downsides.** We’ll have an Appium server and two platform drivers to maintain. Xcode or Android WebView updates can require driver changes. Parallel runs need separate devices, and sessions sharing a runner need separate driver ports. [iOS driver compatibility](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/system-requirements/) · [Android WebView driver](https://appium.github.io/appium-uiautomator2-driver/latest/guides/hybrid/) · [Android parallel runs](https://appium.github.io/appium-uiautomator2-driver/latest/guides/parallel-tests/)

Before committing, list the screens and shared controls by app build and role. Mark where a flow moves between native controls and a WebView, and which controls need a test ID or a device-specific action.

**Possible mix.** If Detox handles native screens well and hits a repeatable Stripe blocker, it could own the native suite while Appium owns the full checkout from **Explore** to the issued ticket. Add a second tool once it proves the missing flow on both platforms. Use separate CI jobs, isolated test data, and the same report format.

## Hardware checks

A hosted phone can exercise the app on physical hardware. Showpass’s reader and printer checks also need the actual terminal or peripheral. If we explore these workflows, record which steps the tool can drive and which need a person. Appium on our own iPad needs a device build and a signed WebDriverAgent. [iOS device signing](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/provisioning-profile/)

- **Camera Check In.** Scan a single-use ticket twice. Showpass should record one admission and reject the second scan. [Camera scanner](https://github.com/showpass/showpass-frontend/blob/f1ca342cd7d5b109446631515c2248c17251dcc6/packages/mobile/src/components/Scanner/CameraScanner/CameraScanner.tsx#L145-L189)
- **Point of Sale and Tap to Pay.** Use a physical iPad for iPad Point of Sale. Present a test card and check the saved payment. Stripe supports physical sandbox test cards. Square’s iOS Sandbox uses mock readers. Confirm the phone and provider for Tap to Pay. [Stripe reader testing](https://docs.stripe.com/terminal/references/testing) · [Square reader testing](https://developer.squareup.com/docs/mobile-payments-sdk/ios/pair-manage-readers)
- **Receipt printing.** Print on the Venue’s Verifone V660p or Star printer. Check the amount or order reference on the paper. [Receipt printer code](https://github.com/showpass/showpass-frontend/blob/f1ca342cd7d5b109446631515c2248c17251dcc6/packages/mobile/src/hooks/dashboard/pos/printing/useReceiptPrinter/index.ts#L202-L229)
